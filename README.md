# DentalAI

Capstone portfolio project. A FastAPI + SQLAlchemy backend with a Groq function-calling agent that handles dental practice scheduling: checking slots, booking appointments, managing recalls, and drafting outreach messages. Built to close skill gaps for AI Automation / Applied AI / Full-Stack roles.

---

## Stack

| Layer | Technology |
|-------|-----------|
| API | FastAPI 0.111 |
| ORM / DB | SQLAlchemy 2.0, SQLite (dev), Alembic migrations |
| Agent | Groq (llama-3 function-calling), 14 tools |
| Logging | python-json-logger, PHI redaction (Ontario PHIPA) |
| Tests | pytest, in-memory SQLite fixture |
| CI | GitHub Actions (ubuntu-latest, Python 3.11) |

## M1 — Reliability Foundation

**Goal:** make the codebase safe to ship: structured logging with PHI redaction, schema migrations, and a test suite that runs on a clean checkout with no external services.

### What was built

**Structured JSON logging with PHI redaction**
Every log line is a JSON object with a `request_id` field threaded through the FastAPI middleware. Before any log record is emitted, a `PhiRedactingFilter` strips email, phone, and date-of-birth values from:
- JSON key-value pairs (`"email": "..."`)
- Python repr output (`'email': '...'`)
- Query-string parameters (`email=...`)
- Bare values in exception tracebacks (email addresses, quoted dates, phone numbers in multiple formats)

Five regex patterns applied in a specific order prevent partial matches (e.g. a space-format phone in a query string was previously left half-redacted). Bearer tokens never appear in structured log output. Took 4 rounds of external review to close all edge cases.

**Alembic migration**
Hand-written initial migration capturing all 8 tables (patients, providers, locations, appointment\_types, appointments, available\_slots, patient\_recalls, events). Written manually rather than autogenerated because the dev database already had tables from `create_all()` — autogenerate produced an empty diff. Configured with `render_as_batch=True` (required for SQLite ALTER support) and `compare_type=True` (detects column type changes).

**Test suite**
45 tests across 3 files, all passing on a clean checkout with no `dentalai.db` and `DATABASE_URL` unset:

| File | Tests | What it covers |
|------|-------|---------------|
| `test_logging.py` | 24 | JSON structure, request ID, PHI redaction across all formats |
| `test_agent_tools.py` | 19 | Agent tool functions via in-memory SQLite fixture |
| `test_health.py` | 2 | App startup, health endpoint, patients endpoint |

Key isolation decision: `conftest.py` creates a fresh `sqlite:///:memory:` database per test and patches both `app.agent.agent.SessionLocal` and `app.events.bus.SessionLocal`. Patching only the agent module left `emit_event()` writing to the missing dev database — caught by a clean-checkout review run.

**GitHub Actions CI**
`.github/workflows/ci.yml` runs on every push and PR to `main`: installs dependencies, runs `alembic upgrade head` against a fresh SQLite file, then runs all 45 tests.

### Numbers

- 45 tests, 0 failures on clean checkout
- 4 rounds of PHI redaction review to close all edge cases
- 1 hand-written migration, 8 tables, 0 autogenerate drift
- 5 PHI regex patterns; ordering matters (phone-bare before query-string)

### Known gaps (later milestones)

- Auth not implemented: `/api/v1/patients` is open; `test_health.py` reflects this
- No latency or cost benchmarks yet (no live traffic)
- Migration drift test not wired into CI

## Running locally

```bash
cd backend
pip install -r requirements.txt
alembic upgrade head
py -m uvicorn app.main:create_app --factory --reload
```

Run tests:

```bash
cd backend
py -m pytest tests/ -v
```

Set `GROQ_API_KEY` in `backend/.env` to run live agent e2e tests (skipped automatically when absent).
